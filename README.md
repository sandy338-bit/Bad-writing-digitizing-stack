# ScrawlGuard

A local web app for HNX26EPS04: digitizing difficult handwriting while exposing uncertainty. It stores uploaded photos and results, runs bounded background jobs, shows word evidence and image crops, accepts human corrections, and exports editable text.

## Run locally

Python 3.11 is recommended. From this folder:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

If `.env` does not exist, copy `.env.example` to `.env`. Set `VISION_READER=ensemble` to run TrOCR, Gemini, and Qwen-VL together. You can still test each one independently with `VISION_READER=trocr`, `gemini`, or `qwen`. The ensemble uses a local TrOCR ONNX checkpoint, a Gemini API key, and Qwen through Ollama by default. Install [Ollama for Windows](https://ollama.com/download/windows), run `ollama pull qwen2.5vl:3b`, and keep `QWEN_BACKEND=ollama`. Alternatively, set `QWEN_BACKEND=dashscope`, create an [Alibaba Cloud Model Studio API key](https://www.alibabacloud.com/help/en/model-studio/get-api-key), set `DASHSCOPE_API_KEY`, and use the [base URL for that key's region](https://www.alibabacloud.com/help/en/model-studio/base-url) in `QWEN_BASE_URL`. Keep keys in `.env`, which Git ignores. Existing environment variables override `.env`. Start the API:

```powershell
.venv\Scripts\python -m uvicorn pipeline.api:app --host 127.0.0.1 --port 8000
```

Open the [review workspace](http://127.0.0.1:8000/) to upload a real handwritten photo. The app shows the source image, word boxes, a prioritized review queue, reader candidates, editable corrections, page verification, exports, and a baseline comparison. Open [API documentation](http://127.0.0.1:8000/docs) for the underlying endpoints. This is a single-process local prototype: use one worker so the in-process queue and restart recovery have one owner. Documents persist in `data/scrawlguard.sqlite3`; the database and keys are ignored by Git.

The review controls can flag low reader agreement, high-risk tokens, and medical terms. A reviewer can accept a reading, replace it, or mark it illegible. Clicking a transcript word zooms to its source on the photo; clicking a photo highlight selects the linked transcript word. Explicitly marked illegible words stay visible in the result and export; they no longer block page verification. The baseline tab compares the same photo's whole-page reading with the pipeline output. Accuracy metrics require labelled ground truth and are generated by the benchmark script, not inferred from an unlabelled upload.

When PaddleOCR is unavailable, the app uses one whole-page request to the selected vision reader instead of one request per detected region. It aligns lines only when the line counts agree; otherwise every word is explicitly linked to the full page rather than claiming a precise location. This reduces API usage but remains single-reader evidence, so all text requires review. If the provider quota is exhausted, the original upload stays available for retry or a clearly labelled manual transcription. A manual transcription is not presented as model output and remains subject to page review.

Reader selection is explicit: Qwen mode does not use the Gemini key, and Gemini mode does not use the Qwen key. The local Qwen model runs on this machine and may be slow on a CPU. Old documents retain their original evidence and can still be reviewed. Restart the server after changing `VISION_READER`, `QWEN_BACKEND`, or a key, then click **Retry analysis** on a failed upload. Cloud quota errors require available provider quota or a key with available quota.

In ensemble mode, each available reader runs independently. TrOCR supplies approximate line locations, while Gemini and Qwen supply whole-page omission checks and line-crop readings, up to `ENSEMBLE_CROP_LIMIT` lines. The result stores each reader's candidate and flags disagreements. If TrOCR misses much of a page, the app links the vision readings to the full page and requires human review. A failed or quota-limited reader is reported in warnings while the others continue. The comparison tab shows independent page readings alongside the combined text. No model output is labelled 90% accurate by the app: measure character and word accuracy on unseen, human-transcribed images with `python -m benchmarks.evaluate path/to/manifest.jsonl --split test --ablation`. The report includes `meets_90_percent_word_accuracy` and individual-reader ablations. This target is not guaranteed, especially for severe handwriting or mixed scripts.

To test TrOCR alone, set `VISION_READER=trocr` and `ENABLE_PADDLE_OCR=false`. Install its optional runtime and download the public checkpoint:

```powershell
.venv\Scripts\python -m pip install -r requirements-trocr.txt
.venv\Scripts\python scripts\download_trocr.py
```

TrOCR reads one text line at a time. The app uses the quantized ONNX conversion of `microsoft/trocr-small-handwritten` through ONNX Runtime, so it does not require PyTorch. It detects approximate line bands, reads each crop, and flags every word for review because there is no independent second reader or page audit in this mode. The checkpoint is stored under `data/models/` and ignored by Git. Very dense or overlapping lines can defeat this simple line detector; inspect the source image before trusting the output.

The queue score is review priority, not the probability that a word is wrong. Single-reader words receive a high minimum priority. Previously saved results are adjusted when read so an old low score is not presented as reassuring evidence.

## Readers and layout

The full pipeline uses PaddleOCR for independent OCR and layout, plus the selected vision reader for crop reading, constrained correction, and a whole-page omission audit. Install the optional CPU reader with:

```powershell
.venv\Scripts\python -m pip install -r requirements-ocr.txt
```

For GPU setups, follow the [official PaddleOCR installation instructions](https://www.paddleocr.ai/main/en/version3.x/installation.html). Weights download on first use. On this Windows host, application control blocks Paddle's native DLL. Set `ENABLE_PADDLE_OCR=false` to avoid that import when running locally. The selected vision reader then reads the page once; OpenCV supplies possible line regions for cautious source linking. OpenCV is a geometry detector, not an independent reader: these single-reader results remain flagged for review.

A Linux CPU container configuration is included:

```powershell
docker compose up --build
```

Set `ENABLE_PADDLE_OCR=true` in `.env` for the full container pipeline. Docker Desktop is not installed on this host, so the container build has not been verified here. Document storage and OCR model caches use named volumes. The compose port binds to localhost.

## Frontend API contract

Uploads use multipart field `file`. Supported formats are PNG, JPEG, WebP, and single-page TIFF. Images are converted to RGB and EXIF orientation is applied. Stored image coordinates and region boxes refer to this normalized image. Byte and pixel limits are enforced before recognition. Multi-page and animated images are rejected instead of silently losing pages.

| Endpoint | Purpose |
|---|---|
| `GET /` | Local upload and review workspace |
| `GET /health` | Liveness, reader configuration and initialization warnings; does not expose keys |
| `POST /v1/documents?correction=true` | Store an image and queue recognition; optional constrained correction switch; returns HTTP 202 and document ID |
| `GET /v1/documents?limit=20&offset=0` | Paginated document summaries |
| `GET /v1/documents/{id}` | Job state, revision, result, or failure message |
| `POST /v1/documents/{id}/retry` | Requeue a failed job |
| `POST /v1/documents/{id}/manual-transcription` | Continue reviewing a failed upload with manually entered text linked to the full page |
| `GET /v1/documents/{id}/image` | Normalized page PNG; use `?annotated=true` for region overlays |
| `GET /v1/documents/{id}/regions/{region_id}/image` | Padded region crop |
| `GET /v1/documents/{id}/review-queue` | Actionable words ordered by risk; accepts `min_agreement`, `strict_high_risk`, and `medical_terms` |
| `GET /v1/documents/{id}/words/{word_id}/image` | Approximate word crop from the real upload |
| `PATCH /v1/documents/{id}/corrections` | Save human edits with an optimistic revision check |
| `POST /v1/documents/{id}/review-page` | Verify a page after actionable word reviews are resolved |
| `GET /v1/documents/{id}/history` | Before/after human correction history |
| `GET /v1/documents/{id}/export?format=txt` | Export `txt`, `md`, or `json` |
| `DELETE /v1/documents/{id}` | Delete a finished/failed document and its correction history |
| `POST /v1/transcribe` | Direct recognition without persistence |
| `POST /v1/baseline` | Fixed whole-page baseline for the selected vision reader |

The recommended frontend flow is upload, poll the document endpoint until `completed` or `failed`, show image/crops with the result, submit corrections, and download an export. Job states are `queued`, `processing`, `completed`, and `failed`. The queue is bounded; HTTP 429 includes `Retry-After`. On restart, interrupted jobs become `failed` and can be retried. Deleting a running job returns HTTP 409.

Every region contains its pixel `box`, raw `candidates`, proposed `text`, heuristic `confidence`, reasons, and status: `accepted`, `review`, `illegible`, `crossed_out`, or `verified`. Each region also contains `words`. A word includes its own approximate pixel box, `source_scope` (`word_estimate`, `line_estimate`, or `page`), text, candidates, reader agreement, risk score, risk tag, `legibility`, and `eligibility`. Legibility is `legible`, `uncertain`, `illegible`, or `struck`; eligibility is `eligible`, `needs_review`, `illegible`, `excluded`, or `verified`. High-impact tags include numbers, units, negations, medical terms, and probable names. A page also has `page_status` and `page_candidate`. The page candidate can reveal writing missed by the region detector. Do not hide a page-level review warning just because some individual regions were accepted.

Correction example:

```json
{
  "revision": 1,
  "edits": [{"id": "r1", "text": "Corrected handwriting"}],
  "page_reviewed": true
}
```

For one-word review actions, send `word_edits` instead of `edits`:

```json
{
  "revision": 1,
  "word_edits": [{"id": "r1-w2", "text": "5", "action": "replace"}],
  "page_reviewed": false
}
```

`action` is `replace`, `accept`, or `illegible`. Accept can omit `text` and retains the current reading. The review queue supports the artifact's agreement and strict medical-token controls without changing the stored model evidence.

Edits mark the region as `verified` while preserving model candidates. The revision increments; a stale revision returns HTTP 409, unknown or duplicate region IDs return HTTP 422. `page_reviewed` clears the page review flag only when no unresolved review/illegible regions remain. Edits do not increase the machine confidence score. TXT/Markdown exports preserve review markers; JSON also includes candidates, warnings, revisions, and correction history. Machine `result.text` is the editable transcript, so clients must show its companion statuses.

## Uncertainty and evaluation

Reader disagreement, low OCR score, low sharpness, speculative correction, and unavailable readers cause review. Unreadable strokes become `[[illegible]]`. If every recognition call fails, the job fails rather than claiming a completed illegible transcription. Model calls have a configurable timeout and the region count is bounded.

`confidence` is a heuristic evidence score, **not** a calibrated probability. Tune `ACCEPT_THRESHOLD` on development annotations, freeze it, and evaluate on writer-disjoint test samples. There is no claim of beating the baseline without such data. See `data/README.md` for annotation policy and `benchmarks/example_manifest.jsonl` for the manifest format.

```powershell
.venv\Scripts\python -m benchmarks.evaluate benchmarks/my_manifest.jsonl
.venv\Scripts\python -m benchmarks.evaluate benchmarks/my_manifest.jsonl --ablation
```

The report contains baseline/pipeline CER and WER, category results, detection and automatic coverage, accepted-text error rate, error-flag recall and precision, missing-text page flags, and a risk–coverage curve. Optional ground-truth region boxes enable region metrics. Matching is one-to-one, so missed regions and reused predictions cannot inflate coverage. `--ablation` compares OCR alone and the pipeline without correction; it requires working OCR and incurs extra vision calls. `--split development` selects a separate development run. The evaluator rejects writer IDs shared across splits.

## Verification

```powershell
.venv\Scripts\python -m unittest discover -v
.venv\Scripts\python -m pip check
```

Tests use controlled readers and temporary databases to check the full API workflow, uncertainty, correction conflicts, persistence, queue limits, failure/retry, image validation, and evaluation matching. After configuring the selected reader's key, make a live smoke test with a generated image:

```powershell
.venv\Scripts\python -m tests.live_smoke
```

That command makes billable API calls; it does not measure hard-handwriting accuracy.

## Configuration and boundaries

See `.env.example` for queue size, upload limit, timeout, acceptance threshold, region cap, database path, and allowed frontend origins. CORS defaults to localhost ports 3000 and 5173. The service has no user authentication and is intended for local development; a shared deployment needs authentication and a shared task queue. Images are transmitted to the API of the selected vision provider.

Mixed-script text is preserved when the selected readers recognize it; coverage depends on their language support. Margin detection uses geometry, crossed-out detection is model-assisted, and layout fallback is heuristic. Tables, diagrams, and multi-page PDF reconstruction are stretch work. Real held-out accuracy, confidence calibration, and the Linux OCR runtime remain to be validated with the actual environment and samples.
